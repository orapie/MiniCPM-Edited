# RAG P0：参考资料时间边界和正文预算验证

日期：2026-10-30。范围为 `Iprv_RAG.md` 中设备实测后列出的两项 P0。项目没有修改向量索引、向量模型或角色卡，测试数据库仍为 `three_body_2` / `8145513ad935bd449fe50d72ebb95e895097ef835e8d415e7c033e77796ae84e`。

## 实施

- `CharacterReferenceFilter` 对角色模式的本轮参考候选检查已验证 bundle、数据来源、parent、角色、cutoff 和原文行号；明确在 cutoff 后或跨越 cutoff 的片段、时间/来源未知、未经当前角色授权的 reviewed fact 被丢弃并记入 trace。场景在 cutoff 之前只说明来源时间，不等于说话者已知内容。普通 RAG 不受角色模式过滤。
- `CharacterRagPromptBuilder` 单独给正文按句排序和压缩，拒绝没有足够文字的纯标点或没有完整句子的候选；资料标号、分隔符及正文一起计入 600 字符上限，单条正文上限 130 字。source 范围仍是原候选范围，不是保证每个实际保留句子的精确范围。多个片段之间可能仍存在信息不相关、指代不明确的问题。
- 向量候选 ID、被过滤或被预算淘汰的原因以及引用来源仍通过 trace 观察。角色知识、追问、无答案 gate 和简繁归一化未在此阶段扩展。

## 验证

- `:app:testDebugUnitTest :app:assembleDebugAndroidTest :app:verifyDebugDatabaseAssets`：151 项 JVM 测试通过，APK 数据库文件清单和 fingerprint 通过；新测试覆盖时间边界、不同角色、未知来源、纯标点和 500 字预算。
- Android `DatabaseRetrievalDeviceTest#referenceTimeAndBudget` 与 `#profession`：2 项通过；测试 10.579 秒，包含临时数据包安装，不能作为单轮时延。
- ARM64 模拟器、原先选择的 MiniCPM-V 4.6、同一数据 fingerprint、最多 64 token；分别在修改前后对同样四个固定合成问题进行一次实际模型生成。使用 `AndroidRagOrchestrator → gate → backend → guard` 的设备测试，未通过聊天 UI 完整交互。测试使用同一模型但生成非确定性，不是控制采样参数的多次统计试验。
- 原始会话 `recent_session.json` 测试前后 SHA-256 均为 `cdece280231bc6741d8c96f235b1a06960cd74d1d3d6ddb614dc52b55080873f`。临时测试输出采集后已删除；模型选择保持不变。

## 仍需处理

1. 基于多人物、多问题的标注集合改善查询规范化、目标人物识别和相关句排序；不能用 `evt-115` 或“面壁者”做单例特判。
2. 针对空资料和无可用证据，审视 `RoleplayAnswerabilityGate` 和模型请求；不能因单次输出正确或参考资料为空就假定模型不会猜测。
3. 维持时间过滤和不可信资料边界，扩展旁白、秘密和角色认知的测试。现有时间过滤仅覆盖可确定来源序列的候选，无法证明角色知道所有通过过滤的正文。
4. 用更大的独立标注题集报告召回、最终证据保留、无答案误注入和回答质量；再测设备冷启动、内存与 P50/P95。当前设备实测只是四例、单次采样。
