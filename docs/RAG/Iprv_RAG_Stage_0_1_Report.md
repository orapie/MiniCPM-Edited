# Iprv_RAG 阶段 0、1 实施与验收记录

状态：基础实现已完成，**阶段 0 和阶段 1 的全部验收条件尚未达到**。这里的六例是诊断样本，不能代表整体检索质量，也不能用场景提及代替角色认知或完整的模型回答验证。

## 当前实现

- 保留根目录 `database/` 唯一数据来源、原始 SQLite、角色卡和审核事实；调试原文默认关闭，已有 `raw_prompt_logcat=true` 的显式 preference 仍生效。新增 `RAG_GATE` 日志关联 query hash 与生成前 gate 判定；检索 trace 增加索引版本、候选分数及每个参考候选的片段、parent、来源范围、裁剪字符数和原因。现有会话中的 source 编码不变。
- 新索引 schema `1.2` 将场景按最多 300 个 Unicode code point 切为带 60 字符重叠的窗口，尽量在句号、问号、分号和换行处分割。每个片段标注 parent、起止 code point、原文行号和切分版本；已审核事实保留原 ID 和角色知识边。
- 向量仍为现有 384 维 hash n-gram；同一场景只保留最高排名片段，场景分数为整场景 0.8、片段 0.2 的线性组合。这是小样本比较下用于减少直接按片段最高分带来的回退的试验值，不视作普适最佳权重。
- Python 重建并精确比较索引；Android 校验数据集/来源、片段父项、字符区间、原文内容、行号、覆盖、父向量、维度和归一化。新客户端支持读取 1.1 和 1.2，但旧 APK 不支持 1.2，必须构建并安装新版本；不回退其他知识库。
- schema 变化导致新 fingerprint `8145513ad935bd449fe50d72ebb95e895097ef835e8d415e7c033e77796ae84e`；现有会话继续按 fingerprint 隔离，不删除模型或旧历史。当前阶段不涉及简繁归一化、混合词法排序或追问重写。
