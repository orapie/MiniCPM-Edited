## 验收中发现的问题及处理

### 1. 同名弱匹配掩盖未来事实

早期 cutoff 下询问叶文洁提出的宇宙社会学公理时，未来公理事实被拒绝，但当前职业事实因为共同出现“叶文洁”而被选中。原 gate 只要看见任意已授权事实就允许生成，导致问题的主要未来事实无法触发拦截。

V2 检索现为有匹配但在 cutoff 后取得的事实保留相关性分数；未来匹配比最相关当前授权事实高出 0.15 以上时，即使存在弱相关授权事实也返回未知。两个匹配接近、仅因共名而产生未来候选时仍允许回答；无分数的旧 fixture 保持原有逻辑。回答改为“此事我尚不清楚，不能妄言”，避免把角色尚未得知误说成事件尚未发生。

0.15 是测试驱动的启发式阈值，不是语义理解或可证明的事实判断；复合问题仍可能需要后续优化。回归覆盖公理早晚 cutoff 和“你认识叶文洁吗”这类共名但不询问未来公理的问题。

### 2. 其他人的来历误用说话者资料

“世界杯文件中陆江仙来自哪里”曾被当作询问罗辑自己的来历：通用职业扩展词把罗辑职业事实召回，模型随后可能编造第三人来历。`CharacterQuestionSubject` 现在先判断是否询问说话者自身，只有自身来历才扩展职业词或检索自身 profile。明确询问第三人来历且没有相关证据时，gate 返回未知。

该主体判断由规则实现，既保留“你的个人来历”也区分“你的同学……来自哪里”；它不能覆盖所有代词、省略和复杂句式。现有合法追问仍按 ID 重新授权。

### 3. 可见输出反问

实测关系回答曾先给出态度，再以“我们怎么看他？”反问玩家。输出 guard 现将未引用的问句视为需要修复，最多重试一次；再次失败时使用安全回退。完整引号或书名号里的历史原话可以包含问号，未闭合引号中的问号不会绕过检查。

此规则处理标点形式的问句，无法识别所有无问号的反问，也可能因引用形式不常见而产生误判；它不保证模型一定给出自然、完整的正面回答。

### 4. 本地模型状态与日志

加载新模型前清除 native MiniCPM-V 版本标记；只有成功加载对应 projector 后再设置当前视觉版本，避免先前视觉模型的版本/上下文配置残留给文本模型。

此前 JNI `minicpm-v` 日志会输出格式化 system/user prompt 与逐 token 原文，与 Phase 4 的无正文 trace 设计不一致。现在只记录长度、token 数和状态。实际设备回归中按测试进程过滤 JNI tag，检查三个合成问题/事实片段均未出现在该 tag 中，格式化元数据仍存在。应用内 Final Prompt 查看不受影响；Debug 阶段原文 Logcat 仍需要显式开启 `rag_debug/raw_prompt_logcat`。

## 已知边界

- 当前库只有 3 条独立审核的罗辑短事实，许多问题没有授权证据；不能据此宣称检索覆盖全部原著信息。
- 设备样本中的身份回答仍有“角色”等元叙述，追问和无资料问题也有含糊回答。模型可能漏用已注入事实或编造内容，当前 guard 不是通用事实核验器。真实结果见证据文件。
- 原始场景可被普通 RAG 检索，但不能因为文本相似就注入 CHARACTER_RAG 的角色记忆；人物关系和完整卡在声明 cutoff 前仍受限。
- 按用户最新要求，完成构造不依赖额外模型是否可用；不对未在目标环境充分测试的模型作质量结论。
- 旧小说专用 Android 设备测试和旧 fixture 工厂仍存在；迁移有价值断言、删除失效测试及旧资源是 Phase 6，不应把本报告的生产路径禁用当成删除完成。
