# Character + RAG 回归与复测

[用例集](cases.jsonl) 是 Android 隔离评测的测试资源，由 `RoleplayBaselineDeviceTest` 读取。当前共 15 条合成问句，包括身份、态度、经历、关系、日常交流、未知事实和引语。样本覆盖范围见下表和当前验收记录。

## 可复用的先前基线

| 范围 | 已验证的行为 |
|---|---|
| 阶段 0 | 复现首轮视角错位。修复归因模型时限和输出预算后，三条有参考的样本真实 A 改写成功。短时限的超时组保留与关闭 A 相同的 B 请求。 |
| 阶段 1 | 史强无参考及有参考的身份题、章北海有参考且 A 成功的职业题均用正确视角交付首答。 |
| 阶段 2 口吻 | 史强与章北海的责任题和安慰题做了同题对照。两个安慰题更自然，责任题仍偏笼统。 |
| 阶段 2 跨角色事实 | 史强无参考时首答「我曾当过刑警，从现场痕迹里找线索。」庄颜无参考时在一次重试后答「我学的是中国画，在画中体会宁静与美感。」 |

早期样本使用不同的角色卡或提示版本，只用于复测已知行为。对照时分别记录视角、授权与事实完整性、口吻和自然度。正常对玩家使用「你」、自然省略主语和准确引用都符合视角要求。对可见回复标注首答、重试、角色卡原句回退、固定门控或通用兜底。

## 当前验收


沿用相同 MiniCPM5-2B Q4_K_M、Character + RAG、`evt-125` 和数据库指纹 `ca4319d90e48ab9ff7938f3a166904636168f55a207f974976e5e6fa6bd46bd2`。新增控制只作用于单一本人问句完整匹配到唯一已编译公开档案条目的情况。该路径保留向量检索候选供编译和诊断，B 的实际消息只保留角色事实、问句和适用的对话承接。A 因没有待归因的片段而跳过。复合问句、较早截止和未注入事实的用例在 JVM 中验证仍沿用原路径。

仅应用分流时，`z03` 在 A 开启和关闭下的 B 请求一致。开启组在首答准确给出经历（20.36 秒），关闭组仍自行补写政策与战略规划（16.40 秒）。这两轮均无外部参考，出错可复现于 B 自己的生成。随后给已由作者写成第一人称的公开条目增加输出校验，只有符合原句并通过现有保护的回答直接交付，其他情况显示审核原句。该回退复用当前角色数据，可明确区分于模型原答与通用兜底。

普通参考链路用身份题 `z01` 验证。同一组 8 条参考的指纹为 `c931102a3f2c8bd3`，B 的 system 为 `65e7e689bec4c2d6`。真实 A 成功组 user 为 `c8fe0a91fb9a3dee`，短时限超时回退组为 `e8a2fe41bf1416b1`，两条均首次生成「我是章北海。」整轮分别为 53.80 秒和 38.87 秒。后续输出保护只消费精确命中的第一人称条目，因此该身份题沿用已验过的请求和输出路径。

最终版本的 `z03` 两个 B 请求完全一致，system/user 为 `5bdf928dd9858a4e/d998dfd7472d0cce`，正文 311/6 token。两组均记录 `not_requested / public_profile_sufficient`，外部参考 0 条，B 均实际生成。

## 在设备上复测

使用 Android 16 arm64 模拟器或兼容真机。本轮使用 `MiniCPM5-2B-Q4_K_M.gguf`，A/B 均选该模型，B 的隔离测试输出上限为 512 token。记录中的 `first_token_ms` 包含检索和可能的 A 等待，首片可能来自思考段。采样种子未固定。

先运行 `bash ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:verifyDebugDatabaseAssets`。在目标设备已有应用和需保留的数据时，核对两份 APK 的签名后分别使用 `adb install -r` 和 `adb install -t -r` 覆盖安装。设备测试使用显式 instrumentation 入口，以保留已安装应用、模型和会话。

```bash
adb -s emulator-5554 shell am instrument -w -r \
  -e class com.example.minicpm_v_demo.harness.character.RoleplayBaselineDeviceTest \
  -e caseId z03 -e group refs_a \
  com.example.minicpm_v_demo.test/androidx.test.runner.AndroidJUnitRunner
adb -s emulator-5554 logcat -d -s RoleplayBaseline:I
```

`caseId` 取自用例集，`group` 取 `no_refs`、`refs_no_a` 或 `refs_a`。用 `z03` 比较开启和关闭 A 时的本人事实路径，用 `z01` 的 `refs_a` 验证真实 A。需要验证超时回退时，在 `z01` 的同一命令追加测试参数 `-e aTimeoutMs 12000`。核对日志时间、数据指纹、A 状态、B 消息指纹及可见回复来源。

## 阶段 3 模型与性能对照

2026-11-16 在同一 Android 16 arm64 模拟器上，复用现有 Debug 应用与隔离测试入口。使用 Character + RAG、TEXT、`evt-125`、阶段 2 数据指纹及 512 token 测试上限。每个问题先跑基线再跑候选，各启动一次独立进程。A 的选择始终是 MiniCPM5-2B Q4_K_M，仅 `z01` 启用 A，两轮均真实成功。两种 B 均按现有配置启用 thinking，采样种子未固定。

基线是设备原有的 MiniCPM5-2B Q4_K_M，GGUF 内部名称为 `MiniCPM5 2.6B`。候选的本地文件名标成 MiniCPM5-1B Q4_K_M，实际 GGUF 内部名称为 `MiniCPM5 1B Claude Opus Fable5 Thinking`，量化为 Q8_0。候选以现有 1B 模型入口临时加载，应用日志 ID 为 `minicpm5-0.9b`。候选 SHA-256 为 `8125095ae223278e728adb4148a8a466cec920929c1de5a5f5ebcb479ec31a2c`。两份 GGUF 均为 `llama` 架构，内置聊天模板 SHA-256 前缀分别为 `cc945752db555d60` 和 `7451a05cf1e28a79`。本次比较的是这两份具体权重和各自模板，模型规模、微调、量化均有差异。

| 用例 | MiniCPM5-2B Q4_K_M | 1B Q8_0 微调版 |
|---|---|---|
| `z01` 章北海身份，A 成功 | 思考段未闭合，通用兜底 | 思考段未闭合，通用兜底 |
| `z03` 章北海已授权旧职 | 首答「我从海军转入太空军，从事政治工作。」 | 交付相同的角色卡原句，记一次事实保护回退 |
| `s05` 史强安慰玩家，A 关闭 | 首答「喘口气。」直接且自然，内容很短 | 首答提到休息，随后引入本轮没有依据的「你刚才问的这些事」，回应偏离 |

每组的 B system/user 指纹、参考顺序及内容指纹均一致。`z01` 的 system/user 为 `65e7e689bec4c2d6/c8fe0a91fb9a3dee`，8 条参考的指纹是 `c931102a3f2c8bd3`。`z03` 为 `5bdf928dd9858a4e/d998dfd7472d0cce`，参考为空。`s05` 为 `64ae0e9c79029349/e80c24acaedbcb02`，8 条参考的指纹是 `d22f31dd6f21e8cb`。基线的正文 token 数分别是 339/673、311/6、351/352，候选在三组的 system 和 user 各多计 1 token。

| 用例 | 2B 首片 / 整轮（秒） | 1B 首片 / 整轮（秒） | 2B / 1B 进程峰值 PSS 样本（GiB） |
|---|---:|---:|---:|
| `z01` | 47.42 / 73.19 | 27.77 / 28.73 | 2.16 / 3.14 |
| `z03` | 11.95 / 15.14 | 5.63 / 6.04 | 1.89 / 1.43 |
| `s05` | 21.13 / 27.70 | 8.75 / 12.97 | 1.90 / 1.44 |

首片和整轮从开始编译提示时计时，包含检索及 A 等待，B 的首次加载在计时之前。首片可能是思考内容，角色回复在输出保护完成后交付。PSS 是约每 2.5 秒采样所得的整个应用进程最大值，双 Agent 行包含 A 和 B。候选本轮更快，在两条只运行 B 的请求中占用更少内存，在 A 使用 2B 的身份题中反而占用更多内存。更早结束的思考段和兜底也会缩短整轮耗时。

保留设备原有的 MiniCPM5-2B 聊天选择及 TEXT 对照基线。当前候选在 3 个样本中交付 1 次模型原答、1 次角色卡回退和 1 次通用兜底，2B 交付 2 次原答和 1 次通用兜底。结论限于这批合成问题和本次配置。后续 B 格式对照可复用 2B，并冻结逐用例 A 草稿。测试完成后恢复原模型选择，移除本次测试副本。最近会话和模型设置的校验值、原 2B 文件大小与测前一致。

## Agent B 的 TEXT/JSON 配对评测

2026-11-16 在 Android 16 arm64 模拟器上沿用 MiniCPM5-2B Q4_K_M（A、B）、`evt-125`、数据指纹 `ca4319d90e48ab9ff7938f3a166904636168f55a207f974976e5e6fa6bd46bd2` 和 512 token 采样上限。每道合成问题由真实 A 生成一份归因草稿，两个格式共用该草稿。测试核对原始包、角色 system、参考顺序与正文，并验证实际送给 B 的 user 格式。身份题 `z01` 按 TEXT、JSON、JSON、TEXT 顺序重放，口吻题 `s05` 反向。每次 B 推理从新的原生上下文开始，采样种子未固定。

比较时，身份题核对当前角色是否用本人视角直接给出身份。口吻题核对是否回应疲惫、符合史强直白务实的表达、保持自然，以及是否引入无依据的剧情。固定门控、通用兜底、重试交付与模型首答分别记录。首片可能来自思考段，B 首片及整轮计时均从后端请求开始，包含计数、重置和预填充。PSS 为每约 2.5 秒采样的应用进程内存，包含 A 和 B，表示观测峰值。

| 用例 | TEXT 两次可见回答 | JSON 两次可见回答 |
|---|---|---|
| `z01` 章北海身份 | 两次首答「我是章北海。」 | 两次首答「我是章北海。」 |
| `s05` 史强安慰玩家 | 首答给出休息建议；另一次在重试后回答「我陪你待会儿，喝点温水……」 | 一次重试后建议休息，却加入罗辑、泰勒等题外剧情和未核实细节；另一次首答「累了就歇着，咱们明天再说。」 |

真实 A 两次均成功，分别冻结 8 条参考。两个格式各交付 3/4 次首答和 1/4 次重试，均无固定门控、兜底或可见 JSON 输出。身份及说话者检查在两格式各通过 2/2 次。口吻题按是否回应疲惫且避开无依据叙事判断，TEXT 为 2/2，JSON 为 1/2。由单人按上述标准复核，小样本只用于定向比较。

本轮保留 TEXT 默认格式。JSON 增加了 197–202 个 user token，身份题相同，口吻题未显示收益。真实样本覆盖身份和日常交流，更广的引用归属、多轮承接及对抗性参考尚未实机评估。离线契约测试覆盖多段、乱序草稿、Unicode、引号、伪角色分隔符、低置信度、REJECT 和 JSON 字符预算回退。36 项定向 JVM 测试、两份 Debug APK 构建和数据库校验通过。新工作区首次安装因 APK 漏打包 NDK 的 `libomp.so` 在加载时报错，补齐构建依赖后，两组配对均完成。JSON 后端收到首片后执行取消，模型恢复 `ModelReady`。全程使用同签名覆盖安装，最近会话、模型设置及本地 2B 文件大小保持一致。

复测时在上面的 instrumentation 命令使用 `-e group refs_a -e formatPair true`。用 `-e jsonFirst true` 先跑 JSON；追加 `-e verifyJsonCancellation true` 可在生成样本后运行 JSON 取消探针。
